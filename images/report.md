# Лабораторноа робота 2
**Тема:** Вступ до веб-розробки. Перша сторінка.

## Таблиця запитів (Network)

| Запит (Name) | Метод | Статус | Тип | Розмір |
| :--- | :--- | :--- | :--- | :--- |
| index.html | GET | 200 / 304 | document | ~0.2 kB |
| logo.png | GET | 200 / 304 | png | ~0.2 kB |


## Відповіді на запитання
1. **Яка адреса сторінки в браузері? З яких частин вона складається?**
   Адреса сторінки: `http://127.0.0.1:5500/index.html`. Вона складається з:
   - Протоколу (`http://`);
   - IP-адреси/хосту (`127.0.0.1` — локальна адреса комп'ютера / localhost);
   - Порту (`:5500` — мережеві двері Live Server);
   - Шляху до файлу (`/index.html`).

2. **Скільки запитів зробив браузер при завантаженні сторінки і чому саме стільки?**
   Браузер зробив 2 основних запити (`index.html` та `logo.png`). Спочатку завантажується сам HTML-документ, після чого браузер знаходить у ньому тег `<img>` і надсилає окремий запит для завантаження файла зображення.

3. **Що відбулось, коли ти поставив неправильний шлях до зображення?**
   Запит на завантаження картинки повернув помилку зі статусом `404 Not Found`. Зображення не відобразилося, а замість нього з'явився альтернативний текст з атрибута `alt="Логотип TaskBoard"`.

4. **Чому зміни, зроблені через DevTools, зникли після F5?**
   DevTools змінює копію DOM-дерева лише в оперативній пам'яті браузера. Сам файл `index.html` на диску залишається незмінним, тому при оновленні сторінки (`F5`) браузер знову зчитує початковий файл з диска.

5. **Хто в цій схемі клієнт, а хто сервер?**
   Веб-браузер — це клієнт (надсилає HTTP-запити), а розширення Live Server у VS Code — це сервер (обробляє запити та віддає файли).
